Bloom Mail Kit

Every template below was rendered by MiniJinja through djangors_template::TemplateEngine — the same engine that will render them in production — with fixture data. Nothing here is a mockup.

The five-petal rule at the top of every message is the brand device, built from table cells with bgcolor rather than an image, so the identity survives in clients that block images by default. Semantic colors are taken from the logo's own petals: pink for failure, cyan for success, orange for advisory, purple for billing, blue for invitations.

Email templates

Each renders both an HTML and a plain-text body. Toggle between them to check the text version reads on its own — a text-only client must still get the whole message.

Receipt document

A4, rendered once at payment confirmation and stored immutably. Unlike the emails this is rendered by a print engine, so real CSS is available — but still no web fonts, so the PDF is byte-stable across machines.

Rules this kit enforces

  • Subject lines stay under 60 characters and front-load the specific object, so the failing app is visible in a notification preview.
  • Every message carries a preheader — the hidden 40–90 character line a client shows next to the subject. Left unset, clients fall back to whatever text comes first.
  • Promotional mail carries List-Unsubscribe; transactional mail does not. A receipt is not opt-out, and offering to unsubscribe from one is a dark pattern in reverse.
  • Every rendered body stays under 102KB. Above that Gmail clips the message and hides the footer, taking the unsubscribe link with it. This is asserted at render time, not hoped for.
  • Money is never computed here. Values arrive pre-formatted from Rust, rendered from integer minor units with the invoice currency's own exponent.
  • No web fonts, no flexbox, no grid, no custom properties in the emails — tables and inline styles only, because Outlook and Gmail strip the rest.
  • Backgrounds and text colors are always set together, so a dark-mode client cannot invert one without the other and leave unreadable text.
