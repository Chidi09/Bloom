{#- Bloom transactional/lifecycle email base layout. Design constraints are load-bearing, not stylistic (PHASES-FINAL.md §13.2): tables for layout, every rule inlined on the element, 600px single column, no web fonts, no flexbox/grid/custom-properties, explicit background AND color on every text-bearing element so dark-mode clients cannot invert us into unreadable. Total rendered size must stay under 102KB or Gmail clips the message and hides the footer, unsubscribe link included. The five-cell petal band below the header is the brand device. It is table cells with bgcolor, not an image, so the identity survives with images disabled -- which is the default in a large share of mail clients. Blocks: preheader, eyebrow, heading, lede, content, cta, aside. Context: see each concrete template. `footer` vars are supplied by crate::infra::email_templates for every send. -#} {% block heading_text %}Bloom{% endblock %}

{#- The five petals, as a rule. Fixed pixel widths rather than percentages: a percentage on an empty cell collapses in several renderers, and the band is the one piece of brand identity that must survive with images disabled. Both the `bgcolor` attribute and the CSS property on every coloured cell -- Outlook honours the attribute, most other clients the property, and a renderer that reads only one of the two drops the colour entirely. -#}
