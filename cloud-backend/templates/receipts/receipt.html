{#- Bloom receipt — print/PDF document, A4. Rendered once at payment confirmation and stored immutably in object storage (PHASES-FINAL.md §13.3). It is never re-rendered from live data, so a later plan rename or price change cannot alter a historical receipt. Corrections are issued as a separate credit note. Unlike the email templates this is rendered by a print engine, not a mail client, so real CSS is available. It still uses no web fonts, so the PDF is byte-stable across machines and does not depend on a font server at render time. Every money value arrives pre-formatted from Rust, rendered from integer minor units using the invoice currency's own exponent. No arithmetic here.
