# Bloom Console And CLI Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Brand the default admin as Bloom Console and add guided, target-aware Docker deployment workflows to the CLI.

**Architecture:** Admin templates retain server rendering but adopt Bloom visual tokens and inline identity. CLI deployment detection selects pure data templates for Flutter, JS Native, server, and hybrid projects, with doctor checks consuming the same detection result.

**Tech Stack:** Dart, Bloom server templates, Docker, Compose.

**Spec:** `docs/superpowers/specs/2026-08-31-bloom-console-and-cli-lifecycle-design.md`

## Global Constraints

- No generated artifact may contain secrets.
- Compose is generated by default; `--production-only` omits it.
- Preserve existing public admin customization APIs.

### Task 1: Bloom Console

**Files:** `packages/bloom_admin/lib/src/admin_site.dart`, `packages/bloom_admin/lib/src/templates/admin_templates.dart`, tests under `packages/bloom_admin/test/`.

- [ ] Add failing template assertions for the inline Bloom mark and default Console labels.
- [ ] Add Bloom CSS tokens, responsive shell, card/grid and status/action styles while retaining server-rendered templates.
- [ ] Preserve `logoUrl`, `siteHeader`, `siteTitle`, and `accentColor` overrides.
- [ ] Run `dart test` and `dart analyze` in `packages/bloom_admin`.

### Task 2: CLI Deployment Lifecycle

**Files:** `packages/bloom_cli/lib/src/commands/`, `packages/bloom_cli/lib/src/templates/`, tests under `packages/bloom_cli/test/`.

- [ ] Add target detection tests for Flutter, JS Native, server, and hybrid projects.
- [ ] Implement `bloom deploy init`, `bloom deploy docker`, and `bloom doctor` deployment checks.
