# Bloom JS Native Next-Style DevTools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `bloom js dev` a unified, current Next-style development indicator, diagnostic panel, and error overlay.

**Architecture:** The CLI injects an isolated shadow-DOM client which consumes the existing SSE stream and DOM runtime-error bridge. `bloom_js_native` continues to own runtime diagnostic production, while the CLI owns visualisation and browser-only instrumentation.

**Tech Stack:** Dart 3.4+, `dart:io`, `package:web`, browser CustomEvent/Shadow DOM, SSE.

**Spec:** `docs/superpowers/specs/2026-09-01-bloom-js-native-next-devtools-design.md`

## Global Constraints

- The client is development-only and has no production bundle or dependency impact.
- Error text is inserted with `textContent`; diagnostic payloads remain bounded.
- Existing DDC hot remount and CSS patch behavior must remain intact.
- Maintain the existing `data-bloom-dev-error-overlay` compatibility marker.
